# dd-to-signal: plan

## What this is

A filing redline. Fetch a company's last two 10-Ks, line the paragraphs up, show
what changed. The narrow question, with proof attached: *what did they rewrite,
and is it new?*

Target audience is retail and semi-professional investors on r/algotrading,
r/investing and r/SecurityAnalysis, plus anybody who has ever been told to "read
the 10-K" and bounced off 90,000 words of boilerplate.

## Why it should earn attention

Three properties, in order of how much they matter:

1. **The findings are the post.** "Eleven of twenty-one large caps promoted
   tariffs in their risk factors this year, here is the count" is a Reddit post
   on its own. The tool is what makes the post checkable.
2. **It runs in one command with no key.** The bundled filings mean
   `pip install && dd-to-signal demo` draws something real with no network. Most
   finance repos die at "get an API key, wait for approval".
3. **It refuses to guess.** JPMorgan's risk factors are unreadable, and the tool
   says so instead of reporting no change. A screening tool that hides its own
   blind spots is worse than no tool.

## Architecture

```
edgar/     rate-limited, cached HTTP; ticker -> CIK -> filing URLs
extract/   filing HTML -> blocks -> named sections
diff/      paragraph alignment, then word-level redlines
nlp/       hedging, sentiment, risk topics, from editable lexicons
pipeline   compare two filings, score the difference
report/    terminal and self-contained HTML
samples    bundled real filings, for the offline demo and the tests
```

The dependency arrows all point one way: `report` and `pipeline` know about
`extract` and `diff`, and nothing below knows about anything above. `compare`
and `compare_blocks` are split so the bundled samples run the same comparison
code as a live fetch, rather than a convenient imitation of it.

## The decisions that were not obvious

**Contents-page detection by shape, not proximity.** The first attempt flagged
any window of 30 blocks containing four distinct item anchors. Apple's 10-K has
nothing to report under items 1B, 1C, 2, 3 and 5, stacks all five within twenty
blocks, and got its entire risk factors section skipped. The rule that works is
an unbroken run of *short* blocks, since body prose always breaks the run, plus
the requirement that the entries reappear below.

**Alignment, not line diffing.** Filings reorder. A line diff reports a moved
paragraph as one deletion and one unrelated addition, which is actively
misleading in a tool whose only job is describing change.

**Redline spans cut by offset.** Rejoining tokens produced "U. S." and
'( "EU" )'. There is no set of spacing rules that survives a 10-K.

**Topic verdicts scoped to risk factors.** A filing-wide union hides the actual
event. Every company has always mentioned tariffs *somewhere*; the story is the
year the word moves into the section headed "things that could go wrong".

**Intensity as well as presence.** Binary topic detection said nothing about
Apple, which mentioned tariffs in both years. The 2 to 13 jump is the finding,
and a present/absent model throws it away.

**Signal recalibrated against measured churn.** The first cut capped the churn
term at 25%, and 21 large caps all landed within a point of 65. That is a number
that sorts nothing. Real risk-factor churn runs 13% to 100% with a median of 41%, so the
floor sits at 10% and the ceiling at 75%.

## Status

Shipped in 0.1.0:

- 10-K and 10-Q, five narrative sections, 21-in-24 coverage on large caps
- alignment, word redlines, hedging/sentiment/topic scoring
- terminal output, HTML report, ranked dashboard
- six companies bundled for an offline demo
- 134 tests, CI on Linux and Windows, Python 3.10 and 3.13
- both README GIFs generated by script from real output

## Next, in order

1. **The three unreadable filers.** Intel and United Airlines are heading
   structures, and each one fixed is a percentage point of coverage. JPMorgan
   needs exhibit following, since the primary document points at an exhibit in
   the same accession that is perfectly fetchable.
2. **A real universe run.** S&P 500, one command, published as a static
   dashboard. This is the launch post, and it needs the coverage work first so
   the skipped column is short.
3. **Paragraph-level topic history.** "This risk factor has been rewritten three
   years running" is a stronger signal than any single year's diff, and the data
   is already there, since `--back N` computes it. Nothing surfaces it yet.
4. **8-K support.** Different shape entirely (no year-on-year pair), so it needs
   a different comparison: against the company's own prior language rather than
   against last year's document.

Deliberately not doing: price data, backtests, or any suggestion that the signal
predicts returns. The moment this claims alpha it has to defend a claim it cannot
support, and the honest version is more useful anyway.

## Launch

Post the findings, never the tool. "I diffed 21 large caps' risk factors against
last year's" with the tariff table, and the repo as the method. The r/algotrading
rule against self-promotion is enforced; a findings post with reproducible
numbers is not self-promotion and does not read like it.
